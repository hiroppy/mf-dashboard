# 今月の銀行別キャッシュフロー予測 QA

## 操作と表示の意味

匿名 demo データで確認する場合は、リポジトリルートから次を実行し、トップの「今月の銀行別予測」を開く。

```sh
pnpm --filter @mf-dashboard/db build:demo
pnpm --filter @mf-dashboard/web dev
```

demo 表示の予測基準日は、月後半に実行しても代表候補を再現できるよう当月3日に固定される。本番表示は実際の当日を基準にする。

銀行ごとの現在残高と月末予測残高を確認し、「入出金の詳細」を開くと、日付順の入出金、各入出金後の残高、推定根拠が表示される。

- `実績`: Money Forwardから取得済みの当月入出金
- `予測`: 過去の定期的な入出金から推定した候補（信頼度: high / medium）
- `要確認`: 根拠が少なく、予定日と金額の確認が必要な候補（信頼度: low）

予測は今月だけの参考値であり、将来残高を保証しない。未登録の臨時入出金、振替、計算対象外に設定された取引は反映されない。口座残高と取引の最終更新後に発生した動きも、次回同期までは反映されない。

過去月カレンダー、過去月の予測、任意月への切替はスコープ外である。

## QA 方針

意思決定に使う残高予測のリスクに合わせ、ISO/IEC 25010:2023 から次の品質特性を選ぶ。

| 品質特性   | 主なリスク                                                       | 受入基準                                                                           |
| ---------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 機能適合性 | 入出金の符号、順序、口座分離、月境界の誤りで残高がずれる         | 当月の実績と予測を日付順に適用し、各入出金後残高と月末残高が期待値に一致する       |
| 信頼性     | 二重計上、不正な金額・日付、古い残高基準によって誤った判断を招く | 記録済み候補を重複計上せず、不正入力を拒否し、残高更新後の実績を一度だけ反映する   |
| 使用性     | 状態や限界を誤解し、予測を確定残高として扱う                     | 実績・予測・要確認の意味、推定根拠、今月限定、対象外データをトップ UI で確認できる |

## テスト設計

| ISTQB テスト技法     | 選定理由                                                         | 主な条件                                                                     |
| -------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 同値分割             | 状態・方向・口座種別ごとの代表動作を効率よく確認する             | 実績/予測/要確認、収入/支出、銀行/銀行以外、対象/振替・計算対象外            |
| 境界値分析           | 当日と月初・月末の境界が残高復元と候補採用を左右する             | 月初、当日、月末、前月末、翌月初、残高更新日直前/当日/直後                   |
| デシジョンテーブル   | 記録済み候補の除外条件が説明・分類・金額・予定日の組合せで決まる | identity、分類、金額許容差、日付許容差がすべて一致した場合だけ候補を一度除外 |
| エラー推測           | 金融計算で影響が大きい異常値を補う                               | 負数、安全整数超過、未知/重複口座、重複イベント ID、未来の実績、過去日の予測 |
| チェックリストベース | UI の説明と匿名性を継続的に確認する                              | 状態説明、推定根拠、各入出金後残高、今月限定、PII 不使用、代表 5 候補        |

## 主要シナリオ

1. 当月実績から月初残高を復元し、将来の給与、カード支払い、家賃、ローン返済、税金を順に反映する。
2. 同日の実績を予測より先に適用し、各イベント後残高と日次・月末残高を確認する。
3. 残高更新日より後の実績を現在残高へ反映し、記録済み候補は二重計上しない。
4. 銀行以外の口座、振替、計算対象外、当月外のイベントを予測残高から除外する。
5. 匿名 demo DB と Storybook で代表 5 候補、実績/予測/要確認、プラス/マイナス残高を確認する。

## 対象外と残存リスク

- 過去月カレンダーと任意月切替は検証対象外。
- 臨時入出金や未取得取引は予測できないため、UI の限界説明で誤認を抑える。
- 金融機関側の取引確定時刻や同期遅延は制御できないため、残高基準日と実績ラベルを表示する。
- 本番データの網羅性は匿名テストで再現しない。テスト、Storybook、文書では `data/moneyforward.db` を使用しない。
